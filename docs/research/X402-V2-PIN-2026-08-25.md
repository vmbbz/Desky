## Scope and result

F4x.2a pins the protocol shape used by Desky's provider-disabled Base Sepolia pilot. It adds no wallet, checkout route, merchant credential, production dependency, mainnet capability, or renderer IPC.

The packages are deliberately **not installed** in Desky's root package. The hosted service is not yet a separately deployed package, while Electron packaging can retain root production dependencies even when a module is outside the import graph. The reviewed core HTTP client also follows redirects and uses schemas that admit/strip unknown response fields. Desky's current boundary needs fixed endpoints, no redirects, bounded bodies, and fail-closed exact fields. Re-evaluate the official SDK when the hosted service receives its own package/deployment boundary.

## Admitted pilot profile

- protocol: x402 v2 only;
- scheme: `exact` only;
- network: Base Sepolia CAIP-2 `eip155:84532` only;
- asset: Base Sepolia USDC `0x036CbD53842c5426634e7929541eC2318f3dCF7e` only;
- transfer method: EIP-3009 only;
- token domain: `USDC`, version `2`;
- amount: exact non-zero atomic-unit string from the server quote;
- recipient: configured merchant address, never caller/model supplied;
- release profile: `windows-direct` pilot only;
- quote lifetime: at most five minutes by default;
- facilitator: one configured HTTPS base URL with fixed `/supported`, `/verify`, and `/settle` children, no redirects;
- custody: the user signs with an external user-selected wallet; Desky and its agents never receive a seed phrase or private key.

`src/service/commerce/x402-base-sepolia.ts` creates requirements only from an authoritative `VerifiedCommerceQuote`, strictly validates the echoed resource/requirements and EIP-3009 authorization, normalizes facilitator responses, checks payer and settled amount, bounds I/O, and marks settlement timeout as indeterminate rather than failed.

## Live compatibility probe

On 2026-08-25, `GET https://x402.org/facilitator/supported` returned HTTP 200 JSON and advertised `{ x402Version: 2, scheme: "exact", network: "eip155:84532" }`. This proves discovery compatibility only. It is not transaction, security, SLA, custody, or production-facilitator evidence. The public x402.org endpoint remains testnet-only.

The official repository currently also has open issue `x402-foundation/x402#2832`, reporting a July 2026 CDP `/verify` and `/settle` regression for some spec-compliant v2 payloads. Desky therefore will not assume CDP production compatibility from documentation or `/supported`; its selected facilitator must pass pinned request fixtures and a real funded testnet matrix.

## Remaining F4x.2 gates

F4x.2b now provides durable authorization and settlement evidence, an explicit unknown/pending projection, transaction uniqueness, retry/order-closure blocking, and settled-evidence-only grant. It remains locally provider-disabled.

1. Build the server checkout endpoints and a browser/wallet handoff that returns only a signed payment payload after explicit human confirmation.
2. Run a funded Base Sepolia matrix: success, user rejection, malformed signature, insufficient funds, quote expiry, duplicate/replay, settle timeout, callback loss, and restart reconciliation.
3. Prove purchase-to-grant, clean-device restore, refund/support correction, monitoring, and incident disable.
4. Select and operationally review the production facilitator before any capped Base mainnet direct-build canary.

No mainnet or Microsoft Store commerce is enabled by this pin.
